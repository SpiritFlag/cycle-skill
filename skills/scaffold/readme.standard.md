# README 표준

이 파일은 README의 정본 양식이다. `scaffold`가 이 골격으로 README를 만들고, `close`가 사이클마다 README를 이 기준에 대조한다. 둘 다 이 파일을 읽는다.

**README는 "뭐고, 어떻게 깔고, 뭘 치면 되나"까지만 답한다.** 각 단계가 안에서 무엇을 하는지는 그 절차의 정본(스킬 · 코드)이 답하고, 왜 그렇게 설계했는지는 `docs/design.md`가 답한다. README가 그것을 다시 쓰면 위반이다.

## 골격

절 이름과 순서는 고정이다. 절을 더하지 않는다. 해당 없는 절은 빼되 순서는 지킨다.

```
# {프로젝트명}
{한 줄. 무엇을 하는 물건인가. 마침표로 끝난다.}

## 이게 뭔가
{3문장 이내. 누구를 위해 어떤 문제를 푸나. 핵심 흐름이 있으면 한 줄 그림.}

## 설치
{명령만. 버전 번호는 이 절에서만 허용된다.}

## 사용
{핵심 흐름 하나. 명령 · 예시 · 스크린샷. 표가 필요하면 "이름 · 언제 · 한 줄"까지.}

## 구조
{폴더 트리. 개수를 세지 않는다.}

## 더 보기
{docs/ · CONTRIBUTING · Releases. 항목당 한 줄.}
```

## 금지

| 금지 | 대신 어디로 |
|---|---|
| 상태 · 진행 블록("현재 ~까지 갖춰졌다", "~를 거쳐") | 마일스톤 · GitHub Release |
| 설치 절 밖의 버전 번호 | Release 태그 |
| 이력("~에서 추가됨", "이번 사이클에서", 날짜) | Release 노트 · 사이클 report |
| 세는 숫자("스킬 8개", "테스트 86개") | 없음. 트리가 보여준다 |
| 설계 근거 · 왜 이렇게 만들었나 · 폐기한 것 | `docs/design.md` |
| 자주 묻는 것 · 문제 해결 · 트러블슈팅 | `docs/` 또는 이슈 |
| 다른 정본의 재진술(스킬 본문 · 절차 상세 · 설계 문서 요약) | 그 정본으로 링크 한 줄 |
| 골격 밖의 절 | 없음 |

## 기계 대조

아래를 돌려 0건이 아니면 사용자에게 보여준다. 설치 절 안의 일치는 제외한다.

```
grep -nE "v[0-9]+\.[0-9]+\.[0-9]+" README.md            # 버전 번호
grep -nE "이번 (사이클|버전)|에서 추가|에서 도입|현재 상태|까지 갖춰|를 거쳐|을 거쳐" README.md   # 이력 · 상태
grep -nE "[0-9]+ ?(개|건|종|명)\b" README.md              # 세는 숫자
grep -nE "^## " README.md                                # 절 이름이 골격과 같은지
grep -nE "20[0-9]{2}-[0-9]{2}-[0-9]{2}" README.md         # 날짜
```

## 사람 대조

기계로 못 잡는 것. 읽고 판정한다.

- "이게 뭔가"가 3문장을 넘지 않나.
- "사용"이 스킬 · 명령의 본문을 다시 쓰고 있지 않나. 정본이 다른 곳에 있으면 그리로 보낸다.
- "구조"의 트리가 실제 파일 시스템과 같나(`find . -maxdepth 2`와 대조).
- 이번 사이클의 diff에 README가 반영해야 할 것(새 명령 · 바뀐 사용법 · 옮긴 폴더)이 있나. 반영하되 골격 밖 절은 만들지 않는다.

## 판정

- 기계 대조 0건 + 사람 대조 통과 → 통과. 보고에 한 줄.
- 걸린 것이 있으면 고친 뒤 다시 대조. 판단이 갈리면 사용자에게 보여주고 묻는다.
