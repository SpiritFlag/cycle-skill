# close

사이클을 닫는다. 감사하지 않는다. 배치가 검증한 것을 믿고, 전체 검증 한 번과 결과 절, SPEC 흡수, 정리.

> **공통 규칙**
> - GitHub 접근은 `gh … --json`뿐이다.
> - 산출물에서 사용자는 "사용자"다. 사용자의 말을 원문 그대로 인용하지 않는다.
> - 전제조건은 조용히 확인한다. 통과했다고 보고하지 않는다. 막힐 때만 한 줄.
> - 이슈를 만들지 않는다. 발견의 승격은 사용자가 사이클 밖에서 정한다.

---

## 0. 전제 (조용히)

- 현재 브랜치 `{버전}-{사이클명}`, `docs/cycles/v*/{버전}-{사이클명}.md`가 있다.
- 배치 표 전 배치 `완료` 또는 `미실증`. `미실증` 배치는 그 SC마다 결정 절에 종류(`재현 불가` · `검증 안 함`)와 사유가 있음. 없으면 막는다 — 사용자가 정하지 않은 미실증은 검증 안 된 배치다.
- 배치마다 `B-n:` 커밋이 있다(`git log {통합}..HEAD --oneline`).
- `git tag`에 `{버전}` 없음. 작업트리 깨끗함.
- 검증 명령 · 브랜치 · 종료 훅은 `CLAUDE.md`의 `## cycle` 절에 있다.

하나라도 아니면 무엇이 막는지 한 줄 말하고 멈춘다. 고치는 것은 배치다 — "다음"으로 돌아간다.

## 1. 전체 검증

`## cycle` 절의 자동 검증 명령이 있으면 **한 번** 돌린다. **사이클에서 전체 검증이 도는 유일한 자리다.** 결과(통과 · 실패)만 결과 절에 적는다. 실패하면 멈추고 사용자에게 보인다. 고치는 것은 배치다.

원격 CI는 기다리지 않고 기록하지 않는다. 테스트 파일을 열어 단언 내용을 읽거나 결정 이행을 대조하지 않는다.

## 2. 결과 절

문서 §4 결과를 채운다. **독자는 비서(사용자)와 마일스톤이다.** 코드 이야기는 하지 않는다.

- **SC 판정** — 범위 절의 SC마다 한 줄. 판정은 `됐다` · `미실증(재현 불가)` · `미실증(검증 안 함)` 셋뿐이다. **`부분` · `안 됐다`는 없다.** 그런 SC가 있으면 close가 아니라 배치다 — 멈추고 돌려보낸다. 근거는 배치 번호(`B-n 검증`)와 §1 전체 검증. 미실증은 결정 절의 종류 · 사유를 그대로 옮긴다.
- **최종 검증** — §1의 명령과 결과.
- **다음에 바꿀 것** — 다음 사이클에 실제로 바꿀 것 3줄 이내. 회고 형식(Keep · Problem · Try)은 쓰지 않는다.
- **발견 표** — 결정 절의 `발견:` 행을 옮긴다. `발견 · 어디서 · 비고`. **이슈로 만들지 않는다.** 승격은 사용자가 정한다.
- **이슈 처리 표** — 범위 절 항목 제목의 이슈마다 `닫음 / 이월(남은 것)`. 범위 절 이월 줄의 이슈도 `이월`. **부분 해결은 닫음이 아니다.** 신규 행은 없다. 미실증 SC는 여기 없다 — §3 장부다.

헤더 상태를 `완료`로, 갱신일을 오늘로.

## 3. SPEC 흡수

`docs/SPEC.md`는 "지금 이 시스템이 어떻게 동작하나"의 정본이다. **이번 사이클이 만들거나 바꾼 규칙 · 수치 · 불변식**을 국면별 절에 넣는다. 범위 절과 diff에서 찾는다.

```
# SPEC

## {국면 · 화면 · 서브시스템}

- {규칙 한 줄. 수치는 값 그대로}
```

- **파일이 없고 흡수할 규칙도 없으면 만들지 않는다.** 처음 흡수할 규칙이 생길 때 만든다.
- 국면당 10줄 상한. 넘으면 이번 것을 넣고 더는 참이 아닌 줄을 지운다. 현재값만. 이력 · 설계 근거(왜) · 기획 · 사용법은 쓰지 않는다. 그것은 사이클 문서 · `docs/design.md` · README다.
- 바뀐 동작은 옛 줄을 덮어쓴다. "~에서 ~로 바뀜"이라고 쓰지 않는다.
- 규칙이 아닌 것(구현 세부 · 파일 경로 · 함수 이름)은 넣지 않는다. 다음 start가 코드를 뒤지기 전에 읽는 문서다.

## 4. 리스크 장부

결과 절에 `미실증`이 하나라도 있으면 `docs/cycles/RISKS.md`에 행을 더한다. 파일이 없으면 만든다. 없으면 건드리지 않는다. **어느 버전이 무엇을 안 본 채 나갔는지가 한자리에서 보이게 하는 것**이 목적이다. 백로그와 경쟁시키지 않는다.

```
# 미검증 리스크

| 버전 | SC | 검증되지 않은 것 | 종류 | 사유 | 해소 |
|---|---|---|---|---|---|
```

- 종류는 `재현 불가`(조건이 갖춰지면 볼 수 있다) · `검증 안 함`(사용자가 보지 않기로 정했다) 둘이다. 섞지 않는다.
- 사유는 결정 절에서. 재현 불가면 무엇이 있어야 볼 수 있는지가 사유다.
- **행을 지우지 않는다.** 이번 사이클이 장부의 행을 검증했으면(범위 절이 그 행을 가리킨다) 해소 열에 이 버전을 적는다.
- 링크 없음. 표 위에 문단 없음.

## 5. README 대조

`${CLAUDE_SKILL_DIR}/../scaffold/readme.standard.md`를 읽고 그 절차대로. 이번 사이클 diff에서 README에 반영할 것을 반영하고, 기계 대조 · 사람 대조를 돌린다. 걸린 것은 고치고, 갈리면 사용자에게. 결과 한 줄을 §9 보고에.

## 6. 종료 훅

`## cycle` 절의 종료 훅을 순서대로. 없으면 건너뛴다.

## 7. 커밋 · 머지 · 태그

1. 사이클 브랜치에 커밋 `close: {버전}-{사이클명}`, 푸시.
2. **사용자에게 한 번 묻는다** — 통합 브랜치에 머지하고, 태그를 밀고, 사이클 브랜치를 지워도 되는지. 묻는 경우 셋과 별개로, 되돌리기 어려운 일이라 묻는다.
3. `git switch {통합}` → `git merge --no-ff {사이클 브랜치} -m "merge: {버전}-{사이클명}"` → `git tag -a {버전} -m "{사이클명} — {한 줄}"` → `git push --follow-tags`.
4. `git rev-parse {버전}^{}`가 머지 커밋인지 확인한다.
5. 사이클 브랜치를 지운다. `git branch -d {사이클 브랜치}` → `git push origin --delete {사이클 브랜치}`.
   `-d`는 머지되지 않은 브랜치를 거부한다. `-D`를 쓰지 않는다. 거부되면 지우지 말고 무엇이 머지되지 않았는지 한 줄 보고한다.

릴리즈 브랜치는 건드리지 않는다. 릴리즈도 만들지 않는다.

## 8. 이슈 · 마일스톤

이슈 처리 표대로. **새 이슈는 없다.**

| 행 | 명령 |
|---|---|
| 닫음 | `gh issue close {n} -r completed -c "{버전}에서 처리. {한 줄 근거}"` |
| 이월 | `gh issue edit {n} --remove-milestone` + `gh issue comment {n} -b "{버전}에서 이월. 남은 것: {…}"` |
| 보류 | 이월과 같되 `--add-label hold`, 코멘트에 착수 조건 |
| 폐기 후보 | **닫지 않는다.** 코멘트로 "폐기 후보 — {이유}"만 남기고 사용자에게 번호를 알린다 |

마일스톤에는 코멘트가 없다. 결과 절 전문을 마일스톤 설명 **끝에 덧붙인다**(기존 설명은 그대로): `gh api -X PATCH repos/{owner}/{repo}/milestones/{number} -f description="{기존}\n\n{결과 절}"`. 비서가 이 설명으로 OUT을 읽는다.

마일스톤에 열린 이슈가 남아 있지 않으면 닫는다: `gh api -X PATCH … -f state=closed`. 남아 있으면 그 번호를 사용자에게 보이고 묻는다.

## 9. 보고

- 버전 · 사이클명 · 태그 커밋 한 줄.
- 이슈 처리 요약(닫음 n · 이월 n). 발견 표의 건수와 "승격은 사용자가". 장부에 더한 행이 있으면 SC 번호와 종류. SPEC에 넣은 국면. README 대조 결과 한 줄.
- 사용자가 정할 것(발견 승격 · 폐기 후보 · 마일스톤에 남은 이슈)이 있으면 번호로.
- 배포하려면 `/cycle:release develop` 또는 `main`.

## 하지 않는 것

- 감사 문서. 게이트 통과 표. 합산 수치. report 파일.
- 새 이슈. 릴리즈 생성. 릴리즈 브랜치 전진.
- `not planned`. 부분 해결 닫기. `부분` · `안 됐다` 판정.
- 미실증 SC를 이슈로 만들기. 장부의 행 지우기.
- 흡수할 규칙 없이 `docs/SPEC.md` 만들기. SPEC에 이력 · 근거 쓰기.
- 사용자 확인 없이 머지 · 태그 푸시.
- README에 이번 사이클 이력 쓰기.
