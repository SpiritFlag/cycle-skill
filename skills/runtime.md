# 실행 환경

각 스킬은 작업 전에 이 파일을 읽는다. 사이클 절차는 실행 환경과 무관하게 같다.

## 프로젝트 규칙 파일

- Codex에서는 저장소 루트의 `AGENTS.md`, Claude Code에서는 루트의 `CLAUDE.md`를 쓴다. 이후 절차의 **프로젝트 규칙 파일**은 이 파일을 뜻한다. 도구가 적용하는 상위 · 하위 디렉터리 지침도 존중한다.
- `init`은 해당 파일의 `## cycle` 절만 만들거나 갱신한다. 다른 절과 `AGENTS.override.md`는 건드리지 않는다.
- 현재 환경의 파일에 절이 없고 다른 환경의 파일에 절이 있으면, `init`이 기존 절을 후보로 읽고 검증 명령을 다시 실측한 뒤 현재 파일에 반영한다. 다른 파일은 자동으로 고치지 않는다.
- 두 파일의 절이 다르면 현재 환경의 파일을 기준으로 삼고 차이를 알린다. 임의로 합치지 않는다. 두 환경을 함께 쓰는 프로젝트는 규칙 변경 시 두 절을 맞춰야 한다.
- `init` 이외의 스킬은 현재 환경의 파일에서 `## cycle` 절을 읽는다. 필요한 절이 없으면 현재 환경의 `init` 호출을 안내한다. 자동 로딩 여부를 추정하지 않는다.

## 호출과 리소스

- Claude Code 호출은 `/cycle:<스킬>`이다. Codex는 `$` 선택기에서 cycle 플러그인의 해당 스킬을 선택한다(`$cycle:init`, `$cycle:start #52 #89`, `$cycle:close` 등). 이름이 겹치면 선택기에서 cycle 소속을 확인하거나 스킬 경로를 함께 지정한다.
- 절차에 있는 `/cycle:…` 안내는 Codex에서 해당 `$cycle:…` 호출로 바꿔 안내한다. 인자는 사용자 메시지에서 읽고, 필수 인자가 없으면 기존 절차대로 묻는다.
- 각 스킬 본문의 상대 리소스 경로는 **그 `SKILL.md`가 있는 디렉터리 기준**이다. 프로젝트 작업 디렉터리나 고정 캐시 경로 기준이 아니다. 예를 들어 resume의 `../start/batch.md`는 같은 플러그인의 start 리소스다.

## 명령과 확인

- `git`과 `gh`가 설치된 로컬 저장소가 필요하다. GitHub 인증은 `gh auth status`로 확인한다. 이 묶음에는 MCP 서버나 토큰 설정이 없다.
- GitHub 읽기는 `gh … --json` 또는 `gh api`의 JSON 응답을 사용한다. 쓰기 명령에 지원하지 않는 `--json`을 붙이지 않는다.
- 셸 예시는 현재 운영체제에 맞춰 실행한다. 파일 검색은 `rg --files` 또는 PowerShell `Get-ChildItem`, 부분 읽기는 파일 도구 또는 `Get-Content`, 문구 대조는 `rg` 또는 `Select-String`으로 대체할 수 있다. 명령을 순서대로 실행하고 각 종료 코드를 확인한다.
- 본문 · 노트 등 긴 텍스트는 파일 편집 도구로 만든 뒤 `--body-file` · `--notes-file`로 전달한다. 셸 문자열에 본문을 끼워 넣지 않는다.
- 확인이 필요한 단계도 현재 대화에서 사용자가 이미 승인한 구체적인 범위와 동작이면 다시 묻지 않는다. 새 결정이나 승인되지 않은 발행 · 머지는 실행 전에 검토 가능한 결과를 보여주고 확인받는다. 확인 도구가 없으면 대화로 묻고 답을 기다린다.
- 사이클 하나 = 세션 하나, 서브에이전트 없음, 범위는 사용자 합의라는 원칙을 유지한다. Codex에서도 별도 채팅이나 에이전트로 배치를 넘기지 않는다.
