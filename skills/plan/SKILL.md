# plan

scope에서 합의한 범위를 **코드 수준의 계획**으로 만든다. 산출물이 둘이다. 사용자가 읽는 `plan.md`와 구현 세션이 읽는 `do.md` 골격.

> **공통 규칙**
> - 산출물에서 사용자는 "사용자"다. 사용자의 말을 원문 그대로 인용하지 않는다.
> - 이슈 · 마일스톤을 보지 않는다. 범위는 `scope.md`가 전부다.
> - 코드는 읽기만 한다. 고치지 않는다.
> - 전제조건은 조용히 확인한다. 막힐 때만 한 줄.

---

## 0. 전제

현재 브랜치 `{버전}-{사이클명}`, 그 폴더에 `scope.md`가 있고 `plan.md`가 없다(있으면 검수 루프 §5로 이어간다). 검증 수단은 `CLAUDE.md`의 `## cycle` 절에 있다. 절이 없으면 `/cycle:init`을 안내하고 멈춘다.

## 1. scope 읽기

`scope.md`를 끝까지 읽는다. propose에서 사용자와 합의한 범위이고, **여기 없는 것은 범위 밖이다.** 항목마다 무엇을 · 어떻게 · 왜 · 끝났다는 기준이 있어야 한다.

**범위를 묻지 않는다.** 항목이 모호해 근본 결정을 물어야 한다면 scope가 부족한 것이다. 무엇이 부족한지 한 줄 적고 `/cycle:propose`로 돌아가자고 한 뒤 멈춘다. 코드 레벨의 결정(어느 함수를 어떻게, 어느 구조로)만 여기서 사용자와 맞춘다.

## 2. 실측

scope 항목이 가리키는 코드를 **직접 읽는다.** 파일 · 함수 · 스키마 · 현재 동작 · 이 영역을 덮는 기존 테스트. 추정하지 않는다. 성패를 가르는 사실은 표시한다.

## 3. plan.md

`${CLAUDE_SKILL_DIR}/plan.template.md`로 골격을 만들고 절 하나씩 채운다.

**독자는 사용자다.** 이 언어 · 이 엔진을 모르지만 프로그래밍 기본기가 있는 사람이 따라올 수 있게 쓴다. 개념이 나오면 풀어 설명한다(왜 이런 구조인지, 이 용어가 무슨 뜻인지). 문서 전체를 가볍게 쓰라는 뜻이 아니다. **개념은 쉽게, 내용은 자세하게.**

- §1 바뀌는 것 — 항목마다 지금 → 나중을 설명. 그림이 도움 되면 텍스트 그림.
- §2 결정 — 갈림길이 있었던 것만 D-n으로 선택지 · 대가 · 고른 것 · 이유. 갈림길이 아닌 것은 한 줄. 선택지 개수는 실재하는 만큼.
- §3 성공 기준 — SC-n. 실증 가능한 문장 + 검증 수단(`## cycle` 절에 있는 것만) + **누가 언제 판정하나**. close가 만드는 문서를 근거로 삼지 않는다.
- §4 리스크 — 무엇이 어긋날 수 있고 그러면 어떻게.

## 4. do.md 골격

`${CLAUDE_SKILL_DIR}/do.template.md`로 만든다. **독자는 맥락 없는 구현 세션(Sonnet)이다.** 설명 없이 지시만. 질문 없이 끝까지 구현할 수 있어야 한다.

- 배치 B-n. 3~5파일 단위. 배치마다 **목표 · 파일(신설 · 수정 · 삭제) · 인터페이스(시그니처 · 스키마를 코드 수준으로) · 순서 · 검증 방법(무엇을 실행해 무엇을 보면 끝인가) · 덮는 SC**.
- 테스트도 파일이다. 동작이 바뀌어 깨질 기존 테스트는 "수정"으로 미리 지목한다. 새 테스트는 어느 SC를 단언하는지.
- 배치 순서는 의존 순. 뼈대만 먼저 넓게 치는 배치를 만들지 않는다.
- 진행 표 · 결정 절 · 질문 절은 비워 둔다. do가 채운다.

## 5. 검수 루프

1. 두 문서의 경로만 보고하고 멈춘다. 내용을 요약해 주지 않는다.
2. 사용자가 의견을 준다(어디서 검수할지는 사용자가 정한다). 반영하고 헤더의 갱신일을 바꾼다. 반복.
3. 사용자가 확정하면 두 문서 헤더 상태를 `확정`으로, 커밋 `plan: {버전}-{사이클명} 확정`, 푸시. "새 세션에서 `/cycle:do`" 한 줄.

## 하지 않는 것

- 이슈 · 마일스톤 접근. 범위 질문. 안 2~3개 택일.
- 코드 수정 · 구현 착수.
- plan.md에 배치 · 파일 표를 넣지 않는다(do.md에). do.md에 설명 · 배경을 넣지 않는다(plan.md에).
- `## cycle` 절에 없는 검증 수단을 SC에 붙이지 않는다.
