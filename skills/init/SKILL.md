# init

프로젝트에 cycle 체계를 깐다. **있는 것은 건드리지 않고 빠진 것만 채운다.** 몇 번을 다시 불러도 같은 결과여야 한다.

> **공통 규칙**
> - GitHub 접근은 `gh … --json`뿐이다.
> - 산출물에서 사용자는 "사용자"다. 사용자의 말을 원문 그대로 인용하지 않는다.
> - 전제조건은 조용히 확인한다. 막힐 때만 무엇이 막는지 한 줄 말하고 멈춘다.

---

## 0. 전제

- `git remote -v`에 GitHub 원격이 있다. 없으면 만들라고 안내하고 멈춘다.
- `gh auth status`가 통과한다. 안 되면 `gh auth login`(Enterprise는 `--hostname`)을 안내하고 멈춘다.
- 위 둘이 통과하면 아무 말 없이 §1로.

## 1. 실측

말하기 전에 본다. 결과는 §2에서 한 표로 보여준다.

| 무엇 | 어떻게 |
|---|---|
| 브랜치 | `git branch -a`. 통합 브랜치(`develop`) · 릴리즈 브랜치(`main`)가 있나 |
| 라벨 | `gh label list --json name`. `p1` `p2` `p3` `hold`가 있나 |
| `CLAUDE.md` | 있나. 있으면 `## cycle` 절이 있나 |
| `docs/cycles/` | 있나 |
| 검증 명령 후보 | 테스트 러너 설정 · 테스트 디렉터리 · 패키지 스크립트 · CI 워크플로 · Makefile. 프로젝트 종류(Unity · Node · Python · 문서 전용 등)를 판정한다 |
| CI 워크플로 | `.github/workflows/`. 있으면 어느 브랜치 · 이벤트에 걸려 있나. 기본은 통합 · 릴리즈 브랜치 푸시다. 사이클 브랜치(`v*-*`)나 모든 브랜치에 걸려 있으면 배치 커밋을 푸시할 때마다 돌게 되니 빼기를 권한다. 안내만 하고 워크플로 파일은 건드리지 않는다 |
| 버전 파일 | `package.json` · `ProjectSettings.asset` · `plugin.json` 등 버전이 적히는 곳. 종료 훅 후보다 |
| 이전 체계 흔적 | `docs/PDCA/` · `docs/RULE.md` · `.pdcarc.json` · `.env.local`의 `PDCAW_PAT`. 있으면 **이식 모드**다 |

## 2. 모드와 할 일

실측 결과를 표 하나로 보여주고, 무엇을 할지 항목별로 적은 뒤 **한 번만** 확인받는다.

| 모드 | 판정 | 하는 일 |
|---|---|---|
| 새 프로젝트 | `## cycle` 절 · `cycles/` 둘 다 없음 | §3 · §4 · §5 · §6 전부 |
| 이미 굴러가는 프로젝트 | 일부 있음 | 빠진 것만. `## cycle` 절이 있으면 검증 명령만 점검(§5 점검 모드) |
| 이식 | 이전 체계 흔적 있음 | 위에 더해 §7 |

## 3. 라벨

없는 것만 만든다.

```
gh label create p1 --color d73a4a --description "지금 해야 함"
gh label create p2 --color fbca04 --description "다음 사이클 후보"
gh label create p3 --color 0e8a16 --description "언젠가"
gh label create hold --color cfd3d7 --description "착수 조건이 있음. 조건은 코멘트에"
```

## 4. 브랜치

- 통합 브랜치가 없으면 릴리즈 브랜치에서 만든다. 사용자 확인 뒤 푸시.
- 릴리즈 브랜치 보호(직푸시 금지 룰셋)는 GitHub 설정이라 스킬이 하지 않는다. 안 돼 있으면 한 줄 안내만.
- 이름이 `develop` · `main`이 아니거나 릴리즈 브랜치가 직푸시 금지면 §5의 절에 적는다.

## 5. CLAUDE.md — `## cycle` 절

프로젝트별 규칙은 `CLAUDE.md`에 산다. 스킬 전용 파일을 두지 않는다. `${CLAUDE_SKILL_DIR}/claude-section.template.md`의 절 하나를 `CLAUDE.md` 끝에 붙인다(없으면 만든다). **검증 명령이 이 절의 핵심이다. 이것이 틀리면 그 위에 쌓이는 성공 기준이 전부 헛돈다.**

1. §1에서 찾은 검증 명령 후보를 나열한다. 실행하기 전에 목록을 보여주고 확인받는다.
2. 확인받은 명령을 **적을 형태 그대로** 돌린다. 결과(통과 · 실패 · 소요 시간)를 본다.
3. 문답으로 확정한다. 자동 테스트가 없는 프로젝트(문서 · 설정 전용)는 대신 쓸 수단(문구 대조 · 유효성 검사 · 사용자 육안)을 실측에 맞게 적는다. 느리거나 외부 자원이 필요한 것은 따로.
4. 브랜치 · 종료 훅 · 릴리즈 노트는 **기본값과 다를 때만** 줄을 남긴다. 기본값: `develop` → `main` ff-only, 훅 없음, 제품명은 레포 이름, "-습니다" 체.
5. 절 전문을 보여주고 확인받은 뒤 쓴다. `CLAUDE.md`의 다른 절은 건드리지 않는다.

**점검 모드**(절이 이미 있을 때): 적힌 검증 명령을 적힌 그대로 돌려 아직 옳은지 본다. 틀린 줄만 고친다.

## 6. 폴더

`docs/cycles/`를 만든다. 비어 있어도 된다. 인덱스 파일은 만들지 않는다.

## 7. 이식 (이전 체계에서)

1. `docs/PDCA/`는 **옮기지 않는다.** 그대로 두고 새 사이클만 `docs/cycles/`에 쌓인다.
2. `docs/RULE.md`가 있으면 검증 수단 · 브랜치 · 종료 훅을 §5의 절로 옮기고, 파일은 삭제 대상이라고 안내한다.
3. pdcaw 백로그를 이슈로 옮긴다. `npx --no-audit -y pdcaw@1 backlog list --json`으로 전건을 받고, `todo` · `doing` · `hold` 계열 **열린 항목만** 옮긴다. 닫힌 항목은 옮기지 않는다.
   - 제목은 그대로. 본문은 detail 전문 + 마지막 줄에 출처(`pdcaw {id} · {openedOn}`).
   - priority → `p1` `p2` `p3` 라벨. 보류 계열 → `hold`.
   - 옮기기 전에 표로 보여주고 확인받는다. 옮긴 뒤 원본은 건드리지 않는다.
4. `.pdcarc.json` · `.env.local`은 삭제 대상이라고 안내만 한다. 지우지 않는다.

## 8. 보고

세 줄 이내. 만든 것 · 건드리지 않은 것 · 사용자가 직접 할 것(브랜치 보호, 파일 삭제).

## 하지 않는 것

- 있는 파일 · 라벨 · 브랜치를 덮어쓰지 않는다. `CLAUDE.md`의 다른 절을 건드리지 않는다.
- 확인 없이 명령을 돌리지 않는다. 추측으로 절을 채우지 않는다.
- README · LICENSE · CONTRIBUTING은 만들지 않는다. `scaffold`가 한다.
- 이슈를 닫거나 마일스톤을 만들지 않는다.
