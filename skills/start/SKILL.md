# start

사이클을 연다. 고르기는 사이클 밖이다. 받은 이슈로 **범위를 합의**하고, 배치를 가설로 짜고, 문서 한 장과 마일스톤 · 브랜치를 만든 뒤 **B-1을 바로 시작한다.** 사이클 하나가 세션 하나다 — 이 세션이 close까지 간다.

> **공통 규칙**
> - GitHub 접근은 `gh … --json`뿐이다.
> - 산출물에서 사용자는 "사용자"다. 사용자의 말을 원문 그대로 인용하지 않는다.
> - 전제조건은 조용히 확인한다. 막힐 때만 한 줄.
> - **배치 절 · 결정 절은 세션이 고친다. 범위 절만 사용자 합의다.** 계획은 계약이 아니라 가설이다.
> - **사용자에게 묻는 경우는 셋뿐이다.** (1) 범위의 "무엇을 왜"가 바뀐다. (2) 검증 수단대로 볼 수 없다. (3) `docs/SPEC.md`에 적힌 동작을 바꾼다.
> - 이슈를 고르지도 만들지도 않는다. 서브에이전트를 띄우지 않는다.

---

## 0. 전제

`gh auth status` 통과, `CLAUDE.md`에 `## cycle` 절, 작업트리 깨끗함, 통합 브랜치 위. 절이 없으면 `/cycle:init`을 안내하고 멈춘다.

인자에 이슈 번호가 하나도 없으면 "고르기는 사이클 밖이다. 이슈 번호를 달라" 한 줄로 멈춘다.

## 1. 읽기

1. 인자 이슈 전건: `gh issue view {n} --json number,title,body,labels,milestone,comments`. 다른 마일스톤에 이미 배정돼 있으면 한 줄 알리고 멈춘다.
2. `docs/SPEC.md`. **있으면 코드보다 먼저 읽는다.** 이 시스템이 지금 어떻게 동작하는지의 정본이다. 없으면 건너뛴다(만들지 않는다).
3. `docs/cycles/RISKS.md`의 해소 열이 빈 행. 없으면 건너뛴다.
4. 버전 사다리: `git tag --sort=-v:refname | head`, `gh api repos/{owner}/{repo}/milestones --jq '.[].title'`.
5. 이슈가 가리키는 코드를 **직접 읽는다.** 파일 · 함수 · 스키마 · 현재 동작 · 이 영역을 덮는 기존 테스트. 추정하지 않는다.

## 2. 항목별 합의 ★ 본체

이슈 본문은 추상화 · 축약돼 있다. 그대로 배치로 자르면 오해가 난다. 그래서 **항목마다** 스킬이 먼저 풀어 쓰고 사용자와 맞춘다. 한 항목이 여러 이슈를 해소할 수 있고, 이슈 하나가 항목 둘이 될 수도 있다.

항목마다 실측을 바탕으로 쓴다.

- **무엇을** — 지금 어떤 상태이고 무엇이 어떻게 달라지나. 구체적으로.
- **어떻게** — 어느 층을 어떤 방향으로. 코드 수준이 아니라 접근 수준.
- **끝(SC-n)** — 무엇을 보면 됐다고 할 것인가. 실증 가능한 문장 + 검증 수단. 수단은 `## cycle` 절에 있는 것만.
- **왜 이렇게** — 이 방향인 이유. 버린 길이 있으면 왜. 1~2줄.

한 항목씩 보여주고 의견을 받아 고친다. 왕복이 여러 번이어도 된다. **여기서 합의한 것이 범위 절이고, 이후 세션이 혼자 바꾸지 않는 유일한 절이다.**

- 장부의 미해소 행 중 이번 항목과 같은 화면 · 같은 조건에서 볼 수 있는 것이 있으면 "같은 검증"으로 붙이자고 한 줄 제안한다. 붙으면 항목의 끝 줄에 그 행을 가리켜 적는다. close가 해소 열을 채운다.
- `docs/SPEC.md`에 적힌 동작을 바꾸는 항목이면 그 사실을 항목에 명시한다. 합의가 곧 묻는 경우 (3)의 답이다.
- 같은 이름의 사이클이 `docs/cycles/*/`에 이미 있으면 그때 무엇을 했는지 한 줄 상기시킨다.

## 3. 이름 · 버전

- 사이클명 `<종류>-<대상>`, 케밥. 종류는 `explore`(새 영역) · `adopt`(외부 도입) · `enhance`(기존 개선) · `refine`(정리 · 마감). 둘에 걸치면 지배적인 하나.
- 버전은 최신 태그의 **minor +1**. major는 사용자가 새 시대를 열 때만이라 제안하지 않는다. 마일스톤에 예약된 버전이 있으면 그 다음.
- 이름 · 버전을 범위와 함께 확인받는다.

## 4. 배치

합의한 범위를 배치로 자른다. **지시서가 아니다.** 표 1행 + 메모 1줄. 세부는 구현하면서 정한다.

- 의존 순. 배치당 3~5파일. 뼈대만 넓게 치는 배치를 만들지 않는다.
- 검증은 **그 배치가 건드린 범위**로 좁힌다(특정 테스트 클래스 · 파일 · 필터). 전체 검증 명령을 적지 않는다. 육안은 `육안 {무엇을}`.
- 동작이 바뀌어 깨질 기존 테스트는 메모에 미리 지목한다.
- 합의 중 이번에 하지 않기로 한 이슈는 범위 절 이월 줄에 이유와 함께 적고 마일스톤에 배정하지 않는다.

배치 표는 보여주되 확인은 받지 않는다. 세션이 고칠 수 있는 절이다.

## 5. 산출

범위 · 이름 · 버전을 확인받은 뒤에만.

1. 마일스톤: `gh api repos/{owner}/{repo}/milestones -f title={버전} -f description="{한 줄 목적}"`.
   설명에는 목적문에 이어 사이클 문서 링크를 넣는다 —
   `https://github.com/{owner}/{repo}/blob/{통합 브랜치}/docs/cycles/v{major}/{버전}-{사이클명}.md`.
   **통합 브랜치** 경로로 건다. 사이클 브랜치는 close 뒤 삭제된다. 머지 전까지는 404이므로 진행 중에는 사이클 브랜치에 있다는 것을 한 줄 병기한다. 이미 있으면 재사용하되 링크가 없으면 채운다.
2. 이슈 배정: 이월이 아닌 이슈마다 `gh issue edit {n} --milestone {버전}`.
3. 브랜치: `git switch -c {버전}-{사이클명} {통합 브랜치}`.
4. 문서 `docs/cycles/v{major}/{버전}-{사이클명}.md`. `${CLAUDE_SKILL_DIR}/cycle.template.md`로 골격을 만들고 범위 · 배치 절을 채운다. 결정 · 결과 절은 비워 둔다.
5. 커밋 `start: {버전}-{사이클명}`, 푸시.

## 6. B-1 착수

`${CLAUDE_SKILL_DIR}/batch.md`를 읽고 그대로 B-1을 돈다. 멈추지 않고 이어서 한다. 그 뒤로는 사용자의 "다음"이 프롬프트다.

## 하지 않는 것

- 열린 이슈 목록을 보여주고 고르게 하기. 이슈 만들기(릴리즈를 깨는 버그 제외). 이슈 닫기 · `not planned` · 본문 수정.
- 안 2~3개를 만들어 택일시키기.
- 배치별 파일 · 시그니처 지시서. 배치 절 검수 루프.
- 합의 안 된 항목을 범위에 넣기. 빼고 그 사실을 적는다.
- `docs/SPEC.md` 만들기. close가 흡수할 규칙이 생겼을 때 만든다.
- 문서를 만들고 멈추기. B-1까지 간다.
